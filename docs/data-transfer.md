# 空间数据导入与导出

控制台右上角的“导入 / 导出”用于备份和迁移整个空间。单个 TVBox、阅读、M3U 等源仍通过“添加源”导入。

## HTTP 接口

两个接口均要求管理员 Bearer。以下为应用内部路径；反向代理子路径部署需在前面加相应前缀。

### `GET /api/v1/data/export`

返回 `application/gzip` 附件 `shadow-relay-data-<UTC时间>.tar.gz`。包内包含版本化的 `manifest.json`、加密快照和种子文件，覆盖源、版本、端点、目录、候选、编排、发布、绑定、运行时、加密凭据、体检、反馈、任务与审计记录。

导出在数据库写锁内读取一致的数据，并记录导出审计。主密钥、管理员令牌、数据库连接串和其他环境配置不进入数据包。数据包中的源配置和历史记录可能包含私人信息，应按私密备份保管。

**恢复到另一实例需要单独提供导出实例的 `RELAY_MASTER_KEY`。** 不要将密钥提交到仓库或放在公开下载链接中。

### `POST /api/v1/data/import`

使用 `multipart/form-data`：

| 字段 | 说明 |
|---|---|
| `file` | 必填，`.tar.gz` 或 `.tgz`，压缩文件最大 64 MiB |
| `mode` | `preview`（默认）或 `apply` |
| `sourceMasterKey` | 可选；跨实例迁移时的原主密钥。同实例可留空 |

预览返回各表数量、预计新增和复用数量、快照数、种子文件数、需中止的历史任务数，以及 `keyRequired`。缺少正确密钥时仍可显示数量，但不能执行导入。只有 `applied: true` 表示已导入。

导入采取合并方式：同 ID 且内容一致的记录跳过；有冲突时返回 409，数据库事务整次回滚。目标已有排队或运行中任务时返回 409。导入的历史排队/运行中任务标记失败，避免重放外部动作；操作人可在任务页明确重试。源的启用状态和定时配置保留，正常调度在导入后继续生效。

原快照与凭据在校验后使用**目标实例现有主密钥**重新加密，不修改目标管理员令牌、主密钥或连接配置。错误密钥、缺失快照、无效 gzip、重复归档项、路径穿越、符号/硬链接、不兼容迁移版本均拒绝导入。数据库写入失败不会提交部分记录；失败的快照落盘可能留下未引用文件，不会改变现有快照。种子文件也会检查冲突并在提交失败时还原。

上传接口保留跨站写请求检查。普通 JSON 管理接口仍只接受 JSON。并发导入/导出会返回 409；解压总量上限 128 MiB、单文件 32 MiB、归档项 10,000、数据库记录 100,000。更大的实例应使用离线运维备份流程。

## 旧版数据包

兼容包含 `relay.pgdump`、`data/snapshots/` 和 `seeds/` 的旧包。只解析白名单表的 `COPY` 数据，不执行备份中的建表、函数、触发器或其他 SQL。目标表结构来自当前应用迁移。

PostgreSQL custom 格式需要环境中存在兼容版本的 `pg_restore`。可用 `RELAY_PG_RESTORE` 指定可执行文件；例如 PostgreSQL 17 的 custom dump 需要 17 或更高版本。该工具仅将 dump 解码到本地临时文件，不携带连接参数，不连接数据库。新格式导入/导出不依赖 PostgreSQL 命令行工具。

种子数据优先保存并加载于 `RELAY_DATA_DIR/seeds`，可由 `RELAY_SEEDS_DIR` 显式覆盖；未设置且无持久种子目录时读取本地 `seeds/`。导入后配方即时生效，不需要重启。反向代理需允许至少 65 MiB 请求体（包含 multipart 字段开销）。
